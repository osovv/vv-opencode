# Review protocol: vv-opencode

What counts as an acceptable change in this repo (public OSS, GRACE 4-managed).

## Acceptance

- The diff is minimal and matches the task; existing style; no drive-by refactorings.
- The checks from `implement.md`/`verify.md` were actually run on current code and the output is
  fresh (“I'm sure it passed” is not evidence). For code changes `bun run check` is the minimum;
  reconcile a “1 known flake/failure” status against `known-flakes.md` instead of re-triaging
  someone else's failures from scratch.
- `git status --short` is free of debris: no `dist/`, logs, scratch, or temporary files.
- Commit messages are Conventional Commits without internal ids/paths; no secrets in the diff.

## Project-specific risks (always check)

- **GRACE anchors**: pairing of `START_/END_MODULE_CONTRACT`, `START_/END_MODULE_MAP`,
  `START_/END_BLOCK_*`; the map reflects real exports; anchors were not removed “to simplify”;
  `MODULE_CONTRACT` updated for the new responsibility. If `.grace/` artifacts changed, fresh
  green `grace lint --path .` output must be part of the evidence.
- **User-facing contracts**: commands/flags/exports/config paths changed → README updated in the
  same change; `package.json#exports` consistent (`bun run pack:check`).
- **Config safety**: no silent clobbering of a user config; writes conservative/idempotent; the
  strict v3 schema not weakened; V1 shapes still rejected; the host window `>=2.0.18 <2.0.19` and
  the `@opencode/*` pins not loosened.
- **dist/**: generated by the build and gitignored — must not appear in the diff; if bundled
  sources changed, a fresh local `bun run build` is sufficient.
- **Workflow plugin**: protocol/state/transition changes → integration test
  `bun test src/plugins/workflow.integration.test.ts`; `BLOCKED`/`NEEDS_CONTEXT` remain hard
  stops; fail-closed parsing of tracked results not weakened.
- **Tests**: expectations derive from the contract, not from the implementation's current output;
  tests live next to the code (`*.test.ts`) or as plugin-root integration tests
  (`NAME.integration.test.ts`). A bugfix comes with a regression test whenever the behavior is
  deterministically expressible.

## Red flags

- “Green” without attached output; citing someone else's or stale runs as one's own.
- Editing `.grace/graph|verification` without changing the owning code (and vice versa — code
  without graph sync when modules/dependencies/data flows changed).
- Widening the write scope beyond the task (for example, global user configs).
